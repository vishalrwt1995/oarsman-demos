Shopify Store Ops Copilot: know about the orders that matter, and what went wrong this week

Oarsman Coffee Co. is a made-up online coffee store. Part 1 sends it signed Shopify order webhooks and runs them through our n8n order-alert template: real signature check, real de-duplication, real alert text. Part 2 is the Monday report: what changed, what looks wrong, and which products lose money.

What's real and what isn't on this page
  • RealThe signature check is HMAC-SHA256 of the raw body, compared with the X-Shopify-Hmac-Sha256 header, the same way the template's Crypto and IF nodes do it (done here with your browser's WebCrypto). "Skip repeated deliveries" and "Build order alert" are the template's Code nodes, copied unchanged (nodes.js). The weekly report numbers and charts are the actual output of our e-commerce report scripts.
  • SimulatedShopify, Telegram and WhatsApp. The signing key is a placeholder made for this page. Nothing is sent anywhere.
  • SampleThe store, its orders, customers and sales history are fictional test data.
  • No client has used this yet, so there are no client results. AI tools helped write the template, the scripts and this page.

Send a webhook

Each button is Shopify posting an orders/create event. Try the bad ones too.

What the owner gets

Alert text exactly as the "Build order alert" node writes it: high-value, cash-on-delivery, first order and discount flags, items, ship-to city and a link to the order in Shopify admin (not clickable here: the store is fictional).

Under the hood

The last request as n8n received it, and the signature it computed. A webhook is only trusted if the two signatures match; anything else gets HTTP 401 and is never processed.
